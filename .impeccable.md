## Design Context

### Users
- **Who they are**: Creators, developers, and power users who want to mirror or migrate their Twitter/X presence to Bluesky.
- **Their context**: Accessing a self-hosted or Dockerized web dashboard to verify cross-posting health, manage account mappings, check logs, and run manual backfills.
- **Jobs to be done**: Connect accounts, monitor background cron status, view and search crossposted tweets, debug media or thread posting issues.

### Brand Personality
- Sleek, clinical, technical, and high-density.
- **3-word personality**: Precise, Reliable, Clinical.
- **Emotional goals**: Confidence in automation, clarity of system status, and ease of setup.

### Aesthetic Direction
- **Visual tone**: A modern technical dashboard with high information density, crisp typography, and fine borders.
- **Theme**: Light and dark mode support, using a refined Bluesky-tinted slate/blue and dark carbon neutrals.
- **Typography**: Refined, highly legible sans-serif hierarchy, clean tabular figures for stats/numbers, and crisp monospace text for logs/IDs.

### Design Principles
1. **Absolute Status Clarity**: Never leave the user guessing if a background job is running or when it will run next. Provide real-time-feeling state transitions, progress bars, and helpful error explanations.
2. **Harmonious Bluesky & Twitter Palette**: Use OKLCH color spaces to define tinted neutrals that feel connected to the brand identities of Bluesky (#057afe) and Twitter/X carbon dark neutrals, rather than generic grays.
3. **Impeccable Hover & Focus States**: Every button, input, tab, and card row must react dynamically to hover, active, focus-visible, and disabled states.
4. **Clean Spacing & Information Density**: Align all layout values to a consistent 4pt/8pt spacing scale, using compact components where necessary to keep relevant data visible without scrolling.
